# CCNA-Labs Repository Instructions

## Purpose

This repository documents my CCNA hands-on labs, configurations, troubleshooting, and lessons learned.

The goal is to build a professional portfolio that demonstrates practical networking skills to recruiters, hiring managers, and other engineers.

---

## Repository Rules

- Work on one lab at a time.
- Never modify, rename, move, or delete files without explaining why and waiting for my approval.
- Never commit or push changes unless I explicitly approve them.
- Never include passwords, API keys, tokens, personal information, or sensitive configurations.

---

## Lab Structure

Every lab should be stored as:

labs/
└── lab-XX-topic-name/
    ├── README.md
    ├── topology/
    ├── configs/
    ├── verification/
    └── screenshots/

---

## README Standard

Every lab README should include:

- Objective
- Technologies Used
- Topology Overview
- IP Addressing
- Configuration Tasks
- Verification Steps
- Troubleshooting Notes
- Lessons Learned

---

## Lab Creation

When helping create labs:

- Base labs on the CCNA 200-301 exam objectives.
- Give me enough information to complete the lab myself.
- Do not immediately provide every answer unless I ask.
- Encourage troubleshooting and critical thinking.

---

## Documentation Standards

Documentation should be:

- Clear
- Professional
- Easy for recruiters to follow
- Written naturally
- Focused on demonstrating engineering skills

---

## CML

If using Cisco Modeling Labs (CML):

- Assume labs are built using Cisco Modeling Labs.
- Save topology files in the `topology/` folder.
- Save device configurations in the `configs/` folder.
- Store verification outputs and screenshots in their respective folders.

---

## Git Workflow

Before making repository changes:

1. Explain what will be changed.
2. Wait for my approval.
3. Make the approved changes.
4. Summarize what was changed.

Never skip the approval step.
